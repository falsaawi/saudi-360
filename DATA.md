## data/files — the source documents (1.29 GB, 1,974 files)

The original GASTAT spreadsheets and PDFs, **content-addressed**: a file is stored
once under its own SHA-256, no matter how many releases link to it. Roughly half of
GASTAT's file links are the same document re-linked from an annual compendium, so
this halves the corpus and means phase 2 parses each workbook exactly once.

```
data/files/<first 2 hex of sha256>/<full sha256><ext>
data/files/00/002360481d7ccc28b64c8dee03c84fe57968918c32716205ec16c85de2c50458.xls
```

| Type | Files | Total | Median | Largest |
| --- | --- | --- | --- | --- |
| `.pdf` | 957 | 867 MB | 219 KB | 17.9 MB |
| `.xlsx` | 944 | 415 MB | 268 KB | 23.9 MB |
| `.xls` | 73 | 34 MB | 490 KB | 1.6 MB |

Spread over 256 shard directories so no folder holds thousands of files.

**Not stored:** 48 PDFs over 20 MB, totalling 4.0 GB. Nothing parses PDFs and
provenance needs only the URL, so they are listed in `oversized.csv` and can be
fetched on demand with `python run_crawl.py --max-pdf-mb 0`.

## data/saudi360.duckdb — the warehouse (260 MB)

Query this, not the CSVs. Open with any DuckDB client:

```bash
duckdb data/saudi360.duckdb "SELECT * FROM v_product_coverage ORDER BY n_observations DESC LIMIT 10"
```

| --- | --- | --- |

`fact_observation` holds one reading per (series, period) — the most recent
release that reported it. `fact_revision` keeps the 3.65 M superseded readings
rather than discarding them, so a restatement is recoverable.

## What is safe to delete

- `data/parsed/` — 1.6 GB, rebuildable in ~11 minutes
- `site/cpi.json` — unused leftover
- `data/*.log` — build logs

**Do not delete** `data/files/` (a re-download is ~70 minutes and depends on
GASTAT still publishing the same files) or `data/catalog/` (the index that makes
the store meaningful).
